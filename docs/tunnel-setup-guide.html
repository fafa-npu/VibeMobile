1. 概述与架构

VibeMobile 允许你通过移动设备远程监控和控制 Claude Code 会话。通过 Cloudflare Tunnel，你可以安全地从任何地方访问你的本地服务，无需公网 IP 或端口转发。

2. 前置条件

必需条件

  • macOS 操作系统 (目前仅支持 macOS)
  • Cloudflare 账户 (免费即可)
  • 已在 Cloudflare 托管的域名
  • Node.js 18+ (用于 Web UI)
  • Python 3.10+ (用于 API Server)
  • Claude Code CLI 已安装并配置

可选条件

  • Cloudflare Access (用于添加身份验证保护)
  • 代理服务器 (如果网络环境需要)
💡 提示 如果你还没有域名，可以在 Cloudflare 注册一个新域名，或将现有域名的 DNS 托管迁移到 Cloudflare。

3. 安装必要工具

3.1 安装 cloudflared

cloudflared 是 Cloudflare Tunnel 的客户端工具。

使用 Homebrew 安装 (推荐)
# 安装 cloudflared
brew install cloudflared

# 验证安装
cloudflared --version
手动安装
# 下载最新版本
curl -L https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-darwin-amd64.tgz | tar xz

# 移动到系统路径
sudo mv cloudflared /usr/local/bin/

# 验证安装
cloudflared --version

3.2 安装 mkcert (用于本地 SSL 证书)

VibeMobile 使用 HTTPS 进行本地通信，需要生成自签名 SSL 证书。

安装 mkcert
# 安装 mkcert
brew install mkcert

# 安装本地 CA
mkcert -install

3.3 生成 SSL 证书

在 VibeMobile 项目目录下执行
# 创建证书目录
mkdir -p certs

# 生成证书
cd certs
mkcert localhost 127.0.0.1 ::1

# 重命名证书文件
mv localhost+2.pem localhost.pem
mv localhost+2-key.pem localhost-key.pem

# 返回项目根目录
cd ..
✅ 验证 确保 certs/ 目录下有 localhost.pem 和 localhost-key.pem 两个文件。

4. Cloudflare 账户配置

4.1 登录 Cloudflare

首次使用需要将 cloudflared 与你的 Cloudflare 账户关联。

执行登录命令
cloudflared tunnel login

这将自动打开浏览器，引导你完成授权流程：

  1. 在浏览器中登录你的 Cloudflare 账户
  2. 选择要授权的域名
  3. 点击 "Authorize" 完成授权
💡 提示 授权成功后，证书会保存在 ~/.cloudflared/cert.pem

4.2 验证登录状态

检查证书文件
ls -la ~/.cloudflared/

# 应该看到 cert.pem 文件
# -rw-------  1 user  staff  266 Dec 27 07:40 cert.pem

5. 创建 Tunnel

1

创建新的 Tunnel

执行创建命令
# 创建名为 VibeMobile 的 tunnel
cloudflared tunnel create VibeMobile

# 输出示例：
# Tunnel credentials written to /Users/yourname/.cloudflared/xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx.json
# Created tunnel VibeMobile with id xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
⚠️ 重要 请记录输出中的 Tunnel ID 和 credentials 文件路径，后续配置需要用到。
2

配置 DNS 路由

将你的子域名指向这个 tunnel。

添加 DNS 记录
# 格式: cloudflared tunnel route dns <tunnel-name> <hostname>
cloudflared tunnel route dns VibeMobile vibe.yourdomain.com

# 输出示例：
# Added CNAME vibe.yourdomain.com which will route to this tunnel
3

验证 Tunnel 列表

查看已创建的 tunnels
cloudflared tunnel list

# 输出示例：
# ID                                   NAME        CREATED              CONNECTIONS
# xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx VibeMobile  2025-12-27T00:05:38Z

6. 配置 Tunnel

6.1 创建配置文件

在 ~/.cloudflared/ 目录下创建 config.yml 文件。

~/.cloudflared/config.yml
# Tunnel 基本配置
tunnel: VibeMobile
credentials-file: /Users/你的用户名/.cloudflared/xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx.json

ingress:
  # API 端点 - 路由到后端服务器
  # 使用正则表达式确保只匹配 /api/ 开头的路径
  - hostname: vibe.yourdomain.com
    path: ^/api/.*$
    service: https://localhost:8765
    originRequest:
      noTLSVerify: true  # 接受自签名证书

  # WebSocket 端点
  - hostname: vibe.yourdomain.com
    path: ^/ws$
    service: https://localhost:8765
    originRequest:
      noTLSVerify: true

  # 健康检查端点
  - hostname: vibe.yourdomain.com
    path: ^/health$
    service: https://localhost:8765
    originRequest:
      noTLSVerify: true

  # Web UI - 默认路由
  - hostname: vibe.yourdomain.com
    service: https://localhost:5173
    originRequest:
      noTLSVerify: true

  # 兜底规则 - 返回 404
  - service: http_status:404
⚠️ 关键配置说明
  • path: ^/api/.*$ - 必须使用正则表达式，避免错误匹配包含 "api" 的其他路径（如 /src/services/api.ts）
  • noTLSVerify: true - 必须添加，因为本地使用自签名证书
  • credentials-file - 必须是完整的绝对路径

6.2 验证配置

验证 ingress 规则
cloudflared tunnel ingress validate

# 成功输出：
# Validating rules from /Users/yourname/.cloudflared/config.yml
# OK

6.3 测试 ingress 规则

可以测试特定 URL 会匹配哪个规则：

测试 URL 匹配
# 测试 API 路径
cloudflared tunnel ingress rule https://vibe.yourdomain.com/api/sessions

# 测试 Web UI 路径
cloudflared tunnel ingress rule https://vibe.yourdomain.com/

# 测试源文件路径 (应该匹配 Web UI 规则)
cloudflared tunnel ingress rule https://vibe.yourdomain.com/src/services/api.ts

7. Desktop App 配置

7.1 打开设置

在 VibeMobile Desktop App 中，点击右上角的 ⚙️ 设置图标。

7.2 配置 Cloudflare Tunnel

在设置页面的 "Cloudflare Tunnel" 部分进行配置：

设置项 值 说明
Enable Tunnel 开启 启用 tunnel 功能
Tunnel Name VibeMobile 必须与 cloudflared tunnel create 创建的名称一致
Tunnel Hostname vibe.yourdomain.com 你配置的完整域名
Proxy URL 可选 如果需要代理访问 Cloudflare，填写代理地址如 http://127.0.0.1:7890
💡 快速隧道 vs 命名隧道
  • Tunnel Name 为空：使用 TryCloudflare 快速隧道，生成随机域名（适合临时使用）
  • Tunnel Name 有值：使用命名隧道，使用你的自定义域名（推荐）

10. 故障排除

常见问题

问题 1: "VibeMobile is neither the ID nor the name of any of your tunnels"

原因：Tunnel 尚未创建
解决方案
# 创建 tunnel
cloudflared tunnel create VibeMobile

# 配置 DNS 路由
cloudflared tunnel route dns VibeMobile vibe.yourdomain.com

问题 2: 页面空白，控制台显示 404 错误

原因：ingress 规则配置错误，请求被路由到错误的服务
解决方案
# 检查是哪个服务返回 404
# 如果返回 {"detail":"Not Found"} 说明请求到了 API Server

# 修改 config.yml，使用正则表达式:
# 错误: path: /api/*
# 正确: path: ^/api/.*$

# 重启 tunnel
pkill cloudflared
cloudflared tunnel run VibeMobile

问题 3: WebSocket 连接失败

原因：WebSocket 路径未正确配置，或被 Cloudflare Access 拦截
解决方案
# 确保 config.yml 中有 WebSocket 路由:
- hostname: vibe.yourdomain.com
  path: ^/ws$
  service: https://localhost:8765
  originRequest:
    noTLSVerify: true

# 如果使用 Cloudflare Access，确保 /ws 路径被设置为 Bypass

问题 4: Unable to reach the origin service

原因：本地服务未启动，或端口配置错误
解决方案
# 确认服务正在运行
lsof -i :8765  # API Server
lsof -i :5173  # Web UI

# 确认协议是否正确 (HTTPS vs HTTP)
# VibeMobile 默认使用 HTTPS，config.yml 中 service 应为 https://

问题 5: Cloudflare Access 登录循环

原因：Cookie 未正确设置，或访问策略配置问题
解决方案
# 1. 清除浏览器缓存和 Cookie
# 2. 检查 Cloudflare Access 策略配置
# 3. 确保域名配置正确
# 4. 如果仍有问题，暂时禁用 Access 进行测试

调试技巧

查看 cloudflared 日志
# 前台运行并查看详细日志
cloudflared tunnel --loglevel debug run VibeMobile
测试特定 URL 的路由规则
cloudflared tunnel ingress rule https://vibe.yourdomain.com/api/sessions
cloudflared tunnel ingress rule https://vibe.yourdomain.com/src/services/api.ts

11. 安全建议

11.1 使用 Cloudflare Access

强烈建议为你的 tunnel 添加 Cloudflare Access 保护，这可以：

  • 要求登录才能访问
  • 支持多种身份验证方式（邮箱、GitHub、Google 等）
  • 提供访问日志审计

11.2 配置 Access Application

  1. 登录 Cloudflare Dashboard
  2. 进入 Zero Trust → Access → Applications
  3. 点击 "Add an application"
  4. 选择 "Self-hosted"
  5. 配置应用详情：
    • Application name: VibeMobile
    • Session Duration: 根据需要设置
    • Application domain: vibe.yourdomain.com
  6. 配置访问策略（谁可以访问）

11.3 其他安全建议

  • 定期更新 cloudflared 到最新版本
  • 不要将 credentials 文件提交到版本控制
  • 使用强密码和双因素认证保护 Cloudflare 账户
  • 定期审查访问日志
