# 用户需求分析报告（VibeMobile：Claude Code 远程状态与指令）

> 日期：2025-12-24

## 1. 概览
该需求的本质是“远程可观测 + 远程可控”：当 Claude Code（CLI）在电脑端长时间运行时，用户希望使用手机在外网环境下查看任务进展，并向指定运行中的任务追加指令。

MVP 的成功标准清晰：
- 多任务并行可见
- WebSocket 推送更新
- 手机端可下发命令并回显结果
- 端到端时延目标：60s

## 2. 用户与使用场景
### 2.1 目标用户画像
- 高频使用 AI coding agent（Claude Code CLI）的开发者
- 习惯让任务长时间运行（生成/重构/跑测试/修复等）
- 运行期间会离开电脑（外出/通勤/会议）

### 2.2 典型场景
- 外出/通勤/会议间隙：希望知道任务是否卡住、失败、完成
- 看到新输出后：希望继续引导任务（补充约束、修正方向、追加命令），而不是等回到电脑再处理

## 3. 核心痛点分析
- 信息断层：任务运行在电脑端，用户离开后无法获知状态与输出变化
- 控制断层：缺少低成本、结构化地把“新指令”注入到同一任务会话的能力
- 并发复杂度：多任务并行时需要稳定的任务标识与路由，避免指令串线

## 4. 需求目标与范围界定
### 4.1 MVP 目标
- 手机端展示任务列表（支持同时多个任务并行）
- 展示每个任务状态、更新时间、最近输出片段
- 采用 WebSocket 推送状态/输出更新（轮询仅作为降级）
- 手机端可对指定 taskId 发送 command，并看到送达与处理结果

### 4.2 明确不做（MVP）
- 手机端代码编辑、完整仓库浏览、复杂 IDE 交互
- 多用户协作、权限分级、团队管理等复杂管理能力（后续再讨论）

## 5. 用户旅程（最小闭环）
1. 电脑端启动并开始运行一个任务（产生 taskId）
2. 手机端在外网打开后看到该任务为 running，并持续看到输出更新
3. 手机端对该 taskId 发送一条新指令（command）
4. 电脑端执行该指令并产生新的输出；手机端看到指令结果与新增输出
5. 任务结束后，手机端看到 succeeded/failed/canceled

## 6. 功能需求专业拆解
### 6.1 任务模型（对齐多任务并行）
最小字段建议（与现有需求一致）：
- taskId
- status：running | succeeded | failed | canceled
- updatedAt
- tailOutput：最近 N 行/最近一段文本

状态机（最小）：
- running → succeeded / failed / canceled

### 6.2 状态推送
- 默认通道：WebSocket
- 降级策略：仅在 WebSocket 不可用时使用轮询，作为可靠性兜底

### 6.3 指令下发
- 输入：taskId + command（文本）
- 输出：指令生命周期可追踪（至少：已接收/执行中/完成/失败），并与任务输出关联展示

## 7. 关键非功能性需求（决定成败）
### 7.1 外网可达性（已确认）
- 必须支持手机不在局域网环境也能访问电脑端服务与 WebSocket

### 7.2 安全性
- 至少包含身份认证与传输加密
- 由于具备“远程命令注入”能力，应按高风险控制面设计，避免未授权访问

### 7.3 可靠性与可恢复
- 断网/切后台后可恢复连接并继续看到最新状态（允许短暂重连）

### 7.4 性能与时延
- 端到端时延目标（验收）：60s

## 8. 技术难点与风险评估
### 8.1 最高风险：Claude Code CLI 会话/任务注入（关键路径）
- 必须调研并实现：在任务运行过程中如何将 command 注入到对应 CLI 会话/任务中执行
- 必须满足：
  - 可路由到指定 taskId（多任务并行不串线）
  - 行为可追踪（手机端可见接收/执行/结果）
  - 不依赖人工操作电脑端 UI

建议：研发第一优先级做 Spike/POC 验证可行性，再扩展 UI 与外网链路。

### 8.2 多任务路由与隔离
- taskId 生命周期、资源隔离（日志/输出/指令队列）需要严谨，否则会出现串线/状态错乱

### 8.3 外网暴露带来的攻击面
- 外网入口会显著提升风险；认证/授权/密钥管理必须从第一版开始落地

## 9. 验收标准与可测试性
（与需求文档一致）
- A1：电脑端启动一个长任务后，手机端在不超过 60s 内能看到任务为 running
- A2：任务每产生新的输出，手机端在不超过 60s 内能看到新增内容
- A3：手机端发送指令后，电脑端在不超过 60s 内确认已接收；且该指令的输出可在手机端可见
- A4：断网/切后台后恢复，手机端能重新连接并继续看到最新状态

建议补充并发验收用例（不新增功能，仅补测试）：
- 同时运行 2+ 任务时，对 taskId1 下发命令不得影响 taskId2 的输出与状态

## 10. 里程碑建议（用于组织交付，不扩展范围）
- M1：完成 CLI 会话/任务注入的可行性验证（taskId + 注入 command + 输出回流）
- M2：实现状态/输出采集 + WebSocket 推送，Web 端可看任务列表与 tail 输出
- M3：实现指令下发与指令状态回显，跑通 A1-A4
