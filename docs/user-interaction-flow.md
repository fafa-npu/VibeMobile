# 用户交互流程（面向 Claude Code CLI 用户）

> 目标：让“使用 Claude Code 的人”在离开电脑后，仍能用手机查看任务状态/输出，并向指定运行中任务发送新指令。
> 
> 范围严格对齐需求：[requirements.txt](../requirements.txt)

---

## 1. 用户视角的一句话体验
在电脑上照常跑 Claude Code 任务；出门后打开手机网页就能看到任务列表与最新输出；发现需要纠偏时，直接对某个任务输入一条指令，几秒到 60s 内在手机上看到执行回显。

---

## 2. 角色与组件（用户能感知到的）
- **电脑端（你平时跑 Claude Code 的机器）**
  - 运行：任务 Runner + API/WebSocket 服务
  - 负责：创建任务、采集输出、接收手机指令并路由到指定 task
- **外网接入（让手机在外网能连上电脑端）**
  - 推荐：Cloudflare Tunnel（浏览器直连）
  - 备选：Tailscale（手机装客户端）
- **手机端（Web/PWA）**
  - 负责：展示任务列表/详情、实时输出、发送指令、查看指令状态

> 注意：MVP 不包含“手机端编辑代码/浏览仓库”。

---

## 3. 第一次使用：端到端配置流程

### 3.1 电脑端：安装与启动（一次性）
你需要完成两件事：
1) 确保电脑上已安装并可运行 `claude`（Claude Code CLI）
2) 启动本项目的“任务服务”（Runner + API/WebSocket）

用户交互期望（MVP）：
- 你只需要在电脑端执行一次启动命令（例如启动一个本地服务）。
- 服务启动后会显示：本地访问地址（如 `http://127.0.0.1:xxxx`）以及 WebSocket 连接地址。

电脑端启动成功的验收感知：
- 打开本地网页能看到空的任务列表页。
- 启动一个任务后，任务列表出现新任务。

### 3.2 外网接入：二选一

#### 方案 A（推荐）：Cloudflare Tunnel（手机浏览器直连）
适合你希望“手机无需安装额外客户端”，在蜂窝网络直接打开网页。

用户配置体验（目标）：
- 你在电脑端配置一个 tunnel，把本地服务端口暴露到一个 https 域名。
- 可选（强烈建议）：用 Cloudflare Access 加一层登录/校验（OIDC/邮箱 OTP 等）。

配置完成的验收感知：
- 用手机蜂窝网络打开该 https 地址，可以看到任务列表页。
- 保持页面打开，能持续收到任务输出更新（WebSocket）。

#### 方案 B（备选）：Tailscale（更像“私网访问”）
适合你愿意在手机安装 Tailscale，并希望只对自己的设备开放访问。

用户配置体验（目标）：
- 电脑与手机加入同一个 tailnet。
- 使用 Tailscale 分配的设备域名或 IP 访问电脑端服务。

配置完成的验收感知：
- 手机在蜂窝网络下，通过 Tailscale 网络仍可打开任务列表页。

> 不建议 MVP 直接暴露家庭路由器端口（高风险、运维成本高）。

### 3.3 手机端：首次打开与“添加到桌面”（可选）
手机端形态为 Web（可做 PWA）。

用户首次使用流程：
1. 打开外网地址（来自 3.2）。
2. 完成登录/鉴权（如果启用了 Access/Token）。
3. 可选：在浏览器中“添加到主屏幕/安装 PWA”，以后像 App 一样打开。

验收感知：
- 首次打开后能看到任务列表页。
- 页面在后台切回来仍能恢复连接并看到最新状态（A4）。

## 4. 日常使用：核心交互流程（MVP）

### 4.1 电脑端开始一个任务（创建 task）
用户动作：
- 你在电脑端发起一次 Claude Code 任务（由本项目 Runner 创建并管理），得到一个 `taskId`。

系统反馈（你能在手机端看到）：
- 任务列表出现新任务，状态为 `running`。
- `updatedAt` 刷新。

### 4.2 手机端查看任务列表（多任务并行）
任务列表页应满足：
- 同时展示多个任务
- 每个任务展示：`taskId`、状态、更新时间、最近输出片段

用户动作：
- 点选某个任务进入“任务详情”。

系统反馈：
- 进入详情后能持续看到输出增量（WebSocket 推送）。

### 4.3 手机端查看任务详情（输出流）
任务详情页（MVP）包含：
- 任务状态：running/succeeded/failed/canceled
- 输出区域：展示 tail output（最近 N 行/片段），并持续追加

用户感知标准：
- 新输出在 60s 内出现在页面上（A2）。

### 4.4 手机端对指定任务发送新指令（command 注入）
用户动作：
1. 在任务详情页输入一条文本指令 `command`（例如“继续/修复/改用某方案/重新生成某段”）。
2. 点击发送。

系统反馈（最小闭环）：
- 立即显示“已发送/等待接收”。
- 60s 内显示“电脑端已接收”（A3）。
- 后续显示：执行中 → 完成/失败，并在输出区看到相关回显。

关键约束（防串线）：
- 该指令只影响当前 taskId 对应的任务，会话不可串到其他任务。

### 4.5 任务结束
用户动作：无。

系统反馈：
- 任务状态变为 succeeded/failed/canceled。
- 输出停止追加。

## 5. 断线/切后台/重连（A4 的用户体验）

用户典型行为：
- 手机切到后台（回消息/拍照/锁屏），数分钟后再回来。

期望体验：
- 页面自动重连 WebSocket。
- 重连后至少能看到“最新状态 + 最新 tail output”。

可接受的降级：
- WebSocket 重连失败时，页面提示“连接中/重试中”，并可使用轮询刷新任务状态（如果实现了轮询降级）。

## 6. 服务端配置交互（从用户角度能理解的配置项）

> 这里描述“用户需要设置哪些东西”，不强绑定具体技术实现。

### 6.1 必需配置
- **外网访问方式**：Cloudflare Tunnel 或 Tailscale
- **鉴权方式**：至少一种（例如 Access 登录或 token）

### 6.2 推荐默认值（减少用户配置成本）
- WebSocket 推送默认开启
- 日志/输出默认截断（只保留最近 N 行或 M KB）
- 任务/指令状态默认持久化（即使服务重启也尽量可恢复）

## 7. 常见问题（面向 Claude Code 用户的心智模型）

### 7.1 我需要改变现有的 Claude Code 使用习惯吗？
- 不需要。理想状态是：你仍然在电脑端像以前一样启动任务，只是任务由 Runner 管理并把状态/输出同步到手机端。

### 7.2 多任务并行时怎么避免串线？
- 心智模型：每个任务有唯一 `taskId`。你在手机端发送指令时始终“选定 taskId”。系统必须保证该指令只路由到该任务。

### 7.3 外网访问会不会不安全？
- 这是高风险控制面，必须有认证与加密。推荐 Cloudflare Access 或 Tailscale ACL。
